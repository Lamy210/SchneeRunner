# SchneeRunner v0.1.0 Bootstrap Release Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Publish the first public SchneeRunner `v0.1.0` GitHub Release as an unsigned/unnotarized DMG, create the matching immutable lightweight tag, and make the latest release easy to find from the README.

**Architecture:** Add a one-time, idempotent bootstrap path that runs only from trusted `main`. The bootstrap reuses the existing release artifact/DMG/checksum validation helpers, adds a truthful bootstrap-specific provenance schema instead of fabricating the normal two-stage publisher fields, and creates/verifies the tag and GitHub Release through a dedicated publication script. The existing tag-driven `Release Build -> Release Publisher` path remains unchanged for future releases.

**Tech Stack:** GitHub Actions YAML, Bash, Python 3 `unittest`, GitHub CLI (`gh`), macOS `hdiutil`, existing SwiftPM release build scripts.

**Spec:** `docs/superpowers/specs/2026-10-07-v0.1.0-bootstrap-release-design.md`

## Global Constraints

- Release version is exactly `0.1.0`; tag is exactly `v0.1.0`.
- Release assets are exactly `SchneeRunner-0.1.0.dmg`, `SchneeRunner-0.1.0.dmg.sha256`, and `release-provenance.json`.
- Source repository must be exactly `Lamy210/SchneeRunner` and bootstrap execution must be restricted to trusted `main`.
- macOS support remains macOS 14+ and Swift 6 / Swift Package Manager.
- The bootstrap release is intentionally unsigned and unnotarized; it must not require Developer ID, `codesign`, Gatekeeper acceptance, stapler, or Apple notarization credentials.
- Structural app/DMG validation, executable checks, SHA-256 verification, tag/source binding, and remote asset verification remain mandatory.
- Existing `v0.1.0` tag must never be force-moved. A conflicting tag/release state fails closed.
- Existing normal tag-driven `Release Build -> Release Publisher` behavior must remain unchanged.
- README download target must be stable `/releases/latest`, not a hard-coded versioned asset URL.
- GitHub Actions third-party actions remain pinned by full commit SHA and jobs use least privilege.

## Review Focus

- **Partial prior state:** tag exists but release does not. Bootstrap must continue only when the tag resolves to the intended source SHA; otherwise fail closed. Covered in Task 3 publication tests.
- **Conflicting completed state:** release/tag exist but provenance or asset names do not match the bootstrap contract. Bootstrap must fail rather than overwrite. Covered in Task 3 publication tests.
- **Future `main` pushes after v0.1.0 exists:** bootstrap must stop successfully without rebuilding/releasing v0.1.0 again. Covered in Task 4 workflow/idempotency contract.
- **Remote corruption/inconsistency:** downloaded DMG, checksum, and provenance disagree. Verification must fail. Covered in Task 2 provenance tests and Task 3 publication tests.
- **User download path:** README must keep a stable latest-release URL and clearly identify the unsigned macOS first-launch caveat. Covered in Task 5 README contract test.

### Task 4: Add the one-time trusted-main bootstrap workflow

**Files:**
- Create: `.github/workflows/bootstrap-v0.1.0-release.yml`
- Modify: `scripts/release/test_bootstrap_v0_1_0_release_contract.py`

**Interfaces:**
- Consumes: trusted `main` source, GitHub repository token, existing release build/package/extract/DMG verification helpers, Task 2 provenance CLIs, Task 3 publisher.
- Produces: first `v0.1.0` tag and GitHub Release; future runs become verified no-ops once the release is complete.

- [ ] **Step 1: Extend the contract test for trigger/permission/concurrency behavior**

Require:

- `on.push.branches: [main]` and `workflow_dispatch`;
- `concurrency.group` dedicated to `bootstrap-v0.1.0-release` with `cancel-in-progress: false`;
- a cheap Ubuntu preflight job that detects a completed valid `v0.1.0` release and outputs `release_required=false`;
- the macOS build/publish job runs only when `release_required == 'true'`;
- no Apple secrets/environment dependencies;
- publisher job has `contents: write`, while preflight remains `contents: read`;
- bootstrap never calls or edits the normal `release-build.yml` / `release-publisher.yml` path.

- [ ] **Step 2: Implement preflight state checking**

The Ubuntu preflight checks:

- exact repository/ref identity;
- if no `v0.1.0` release exists, output `release_required=true`;
- if a release exists, require the tag ref, exact three asset names, valid release metadata, and internally consistent downloaded DMG/checksum/bootstrap provenance; when valid output `release_required=false`;
- if partial/conflicting completed state exists, fail rather than silently skipping.

Reuse Task 2 verifier and checksum helper instead of reimplementing JSON/hash rules inline.

- [ ] **Step 3: Implement macOS build/publish job**

Exact sequence:

1. checkout trusted `main` commit with `persist-credentials: false`;
2. assert `GITHUB_REPOSITORY == Lamy210/SchneeRunner` and `GITHUB_REF == refs/heads/main`;
3. set `RELEASE_VERSION=0.1.0` and run `scripts/ci/build-release-artifact.sh`;
4. package `build/SchneeRunner.app` with `package-app-artifact.sh`;
5. extract the package into a clean release input with `extract-app-artifact.sh`;
6. create `release-output/SchneeRunner-0.1.0.dmg` from the extracted app with `create-dmg.sh`;
7. set `RELEASE_SIGNED=false` and run `verify-release.sh`, producing the canonical `.sha256` file;
8. write bootstrap `release-provenance.json` for the exact DMG/source/workflow run;
9. verify that provenance immediately;
10. invoke `publish-bootstrap-release.sh` with `SOURCE_SHA=${GITHUB_SHA}`, `TAG_NAME=v0.1.0`, repository identity, and the three release artifacts.
